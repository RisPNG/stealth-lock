# Private native integration tests

Run `mise exec -- npm run test:shell` with GNOME Shell, GJS, GTK 4, libadwaita, GLib schema tools, D-Bus, a user systemd manager, and unprivileged user/network namespaces available. The fixture was executed on GNOME Shell 48.7. It creates private system and session buses, HOME and XDG directories, and two headless Wayland monitors. Its scrubbed environment forces software rendering; its transient scope limits memory to 1500 MiB, CPU to 150%, tasks to 400, and elapsed time. It does not touch the current desktop or its settings.

Before launch, the runtime `helpers/authentication.py` is replaced and compared against a sentinel-bearing fixture. The same fixture is compared again before crash recovery restarts the compositor. The fixture uses private stdin and controlled exit statuses without PAM. Native scenarios exercise registered activation, actual virtual keyboard and pointer devices, password editing and composition, normal and stealth authentication feedback, subprocess outcomes, modal ownership and cancellation, cursor image decoding and fallback, monitor geometry, live native theme variants, real private-bus MPRIS players and the stock ScreenShield through a minimal private GDM fixture.

The effects tests execute the ordinary saved JavaScript starters through real Bubblewrap-isolated JavaScriptCore workers. Their drawing commands reach native Shell blur and Cairo/Pango layers, including Unicode glyphs and centralized theme colors. They check independent clocks, monitor containment across gaps, live program edits, reduced motion, timer/actor/drawing cleanup and worker reaping. Programs have ordinary JavaScript but no Shell, GI, process, network, password or lock-control APIs. Tests inspect actual update transport while a disposable password is present, reject invalid native drawing output, and terminate infinite init/update/destroy callbacks while input protection remains active. Animations are enabled only inside the private software-rendered compositor.

A real `ExtensionPrefsDialog` client on the private compositor exercises GTK bindings, full schema bounds, enum and color controls, saved CSS previews and CRUD, and accelerator capture, validation, Save, Escape and Backspace reset. It verifies the three inactive first-profile JavaScript starters behave as ordinary saved entries: each can be edited, custom programs can be saved, selected, renamed and deleted, syntax checking uses an isolated worker, Apply refuses invalid JavaScript, and deleting the entire library does not reseed it.

The runner then abruptly kills only the compositor PID found in its owned scope, preserves its private runtime state and settings, and starts a fresh compositor to check marker recovery and dismissal. This verifies extension recovery with an enabled profile, separate from GNOME's normal session failure policy. GNOME may disable extensions after an early Shell crash or end a Wayland session. Recovery requires the extension to load again; a privacy overlay cannot protect the desktop while its compositor is down.

Set `SLH_FAKE_GDM=0` to exercise unavailable native locking. Scenarios requiring stock ScreenShield report explicit skips. Set `SLH_KEEP=1` to retain private logs after the scope stops; otherwise the runner stops its exact scope and removes its temporary files on success or failure. `SLH_NETNS=0` explicitly disables network isolation for environments lacking user namespaces.

The log gate rejects extension diagnostics, native St/GLib/GTK/Clutter warnings and errors, keybinding warnings and allocation failures, except exact declared fixture failures. Missing host services and software-renderer startup messages in the isolated compositor are outside the extension diagnostic gate. Physical input devices, real IBus engine selection, scaling, suspend/resume and display-manager failure policy still require testing on their actual sessions.

The separate Python authentication suite includes real `pam_unix` and `pam_faillock` tests. Bubblewrap maps only the current host UID/GID to namespace root and exposes a private disposable passwd/shadow, administrator-owned `gdm-password` policy and failure tally. Correct/wrong passwords, account/password expiry, locked hashes, lockout/reset, missing services/modules and unsafe policy permissions are checked without reaching the host account or policy. A successful result in this fixture does not validate every distribution's PAM configuration.

Repository CI runs source checks and a GNOME 45–51 native matrix. Each native job uses a digest-pinned official GNOME Mutter Fedora image, installs that Fedora release's runtime, asserts the installed Shell major, and runs this fixture as a dedicated nonroot user inside an owned container with its own systemd. The container has a 2 GiB memory ceiling and two CPUs; the compositor keeps the stricter limits above. Old Fedora releases use signed RPMs from the official Fedora archive. `run-container.sh <major> <pinned-image>` reproduces a matrix job on a development/CI host with Docker and mise; it tests committed HEAD and cleans its container, derived image and temporary files. A configured matrix is not passing evidence: a version is verified only when its actual job succeeds.
