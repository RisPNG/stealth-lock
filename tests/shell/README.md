# Native integration fixture

Run `mise exec -- npm run test:shell` with GNOME Shell, GJS, GTK 4, libadwaita, the GNOME preferences resource, Python, and the package build dependencies installed. The fixture was executed on GNOME Shell 48.7.

The runner builds the extension into a temporary home, starts a private D-Bus session and a headless Wayland compositor with one 1024×768 virtual monitor, and uses GNOME's automation-script interface. It uses memory GSettings and enables only the test extension. The host extension installation, settings, browser, and desktop are not used. The run is bounded to 30 seconds. Cleanup terminates the fixture process group and services identified by its exact runtime directory, unmounts its own document/GVfs mounts, and removes its temporary files.

The fixture checks native password entry and keyboard editing, Return submission, clear/reveal controls, paste and Super suppression, modal action mode, in-memory screenshots, all cursor modes, prompt corner placement, resource cleanup, constructor/setup failure, capture cancellation, and disable/re-enable recovery. Emergency shortcuts are injected through a native virtual keyboard and must retain the privacy screen when native lock is denied. It simulates native composition through Shell's input-method callback to check clear and inactivity behavior. GTK preferences are instantiated in a separate GJS process on the fixture compositor and checked for settings binding, sensitivity, shortcut Save/Cancel, saved CSS CRUD/Apply, retained legacy JavaScript, and dialog cleanup.

Authentication success and ScreenShield lock transitions are test stubs. The fixture does not call the real system lock or check the user's password. Native PAM, actual lock/unlock, real IBus engines and candidate selection, multiple monitors, scaling, and GNOME 45–47 remain manual integration checks. Shortcut Save tests the dialog's persistence with a supplied preview; physical shortcut capture in GTK remains manual. Outside-modal activation uses the extension's activation method: virtual injection resolved the registered native action but did not dispatch its callback in this headless environment. The shared activation shortcut is verified as an emergency handoff while the modal is active.

The runner rejects JavaScript/cleanup failures, native GTK/St/Clutter/GLib/Pango criticals, and actor allocation warnings. The two deliberately injected constructor/setup failures and private-session service startup diagnostics are expected.
