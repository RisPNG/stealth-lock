# Private native integration tests

Run `mise exec -- npm run test:shell` with GNOME Shell, GJS, GTK 4, libadwaita, GLib schema tools, D-Bus, a user systemd manager, and unprivileged user/network namespaces available. The fixture was executed on GNOME Shell 48.7. It creates private system and session buses, HOME and XDG directories, and two headless Wayland monitors. Its scrubbed environment forces software rendering; its transient scope limits memory to 1500 MiB, CPU to 150%, tasks to 400, and elapsed time. It does not touch the current desktop or its settings.

Before launch, the runtime `authentication.py` is replaced and compared against a sentinel-bearing fixture. The fixture uses private stdin and controlled exit statuses without PAM. Native scenarios exercise registered activation, actual virtual keyboard and pointer devices, password editing and composition, normal and stealth authentication feedback, subprocess outcomes, modal ownership and cancellation, cursor image decoding and fallback, monitor geometry, live native theme variants, real private-bus MPRIS players and the stock ScreenShield through a minimal private GDM fixture.

The effects tests construct native Shell blur and Cairo/Pango Neo Rain and City Grow layers, including Unicode glyphs and configurable colors. They check independent clocks, complete monitor containment across gaps, live preset edits, reduced-motion transitions, animation and clock timer release, and drawing resource cleanup. Animations are enabled only inside the private software-rendered compositor to test both movement and static rendering. Invalid executable text is refused without changing privacy ownership.

A real `ExtensionPrefsDialog` client on the private compositor exercises GTK bindings, full schema bounds, enum and color controls, saved CSS previews and CRUD, and accelerator capture, validation, Save, Escape and Backspace reset. It verifies the three inactive first-profile starter effects behave as ordinary saved entries: each can be edited, custom configurations can be saved, selected, renamed and deleted, invalid knobs cannot be applied, and deleting the entire library does not reseed it.

The runner then abruptly kills only the compositor PID found in its owned scope, preserves its private runtime state and settings, and starts a fresh compositor to check marker recovery and dismissal. This verifies extension recovery with an enabled profile, separate from GNOME's normal session failure policy. GNOME may disable extensions after an early Shell crash or end a Wayland session. Recovery requires the extension to load again; a privacy overlay cannot protect the desktop while its compositor is down.

Set `SLH_FAKE_GDM=0` to exercise unavailable native locking. Scenarios requiring stock ScreenShield report explicit skips. Set `SLH_KEEP=1` to retain private logs after the scope stops; otherwise the runner stops its exact scope and removes its temporary files on success or failure. `SLH_NETNS=0` explicitly disables network isolation for environments lacking user namespaces.

The log gate rejects extension diagnostics, native St/GLib/GTK/Clutter warnings and errors, keybinding warnings and allocation failures, except exact declared fixture failures. Missing host services and software-renderer startup messages in the isolated compositor are outside the extension diagnostic gate. Real PAM/GDM authentication, physical input devices, real IBus engine selection, scaling and other supported Shell versions still require testing on their actual sessions.
