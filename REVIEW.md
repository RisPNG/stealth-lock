# Decisions and release review

This is the requested list of requirements not settled by `1.0.md` or the discussion. The rebuild implements concrete defaults so they can be reviewed; a default is not a decision already made by the maintainer. The agreed product is a visible-desktop privacy screen for short absences, with the strongest feasible input/authentication protections and restoration after Shell recovery.

| Review/discuss/decide | Current implementation and open decision |
| --- | --- |
| GNOME/distribution matrix | Metadata retains GNOME 45–48 and X11/Wayland. Automated live checks target the locally available GNOME 48. Decide which versions/distributions to release on, whether to add 49/50, and require successful real-shell testing before expanding metadata. |
| PAM and account policy | Fixed `gdm-password`, UID-derived user, one secret prompt, authentication/account/cleanup all required. Decide whether installations without GDM need a separately provisioned PAM service, and whether fingerprint, smartcard, multi-factor, expired-password changes, or passwordless accounts need native authentication support. No fallback is enabled. |
| Retry policy and feedback | One attempt, ten-second timeout, failure delays 1/2/4/8/16/30 seconds. Normal mode displays distinct denied/unavailable and retry messages; Stealth mode keeps them hidden except diagnostics. Decide whether timing should be configurable and whether audible or additional accessible feedback is needed. Passwords and buffer lengths are never included. |
| Emergency/diagnostic controls | Ctrl+Alt+Shift+L always requests native lock; debug abort shortcut and Escape×5 also hand off. Decide whether debug controls should ship, whether to retire these old key names, and whether users may customize the always-available emergency shortcut. |
| Disable and native lock refusal | Disable requests native locking and retains the recovery marker. GNOME policy, unavailable locking, or a passwordless account can deny that request; Shell still requires extension resources to be removed on disable, exposing the desktop immediately. Decide how to communicate this case and whether distribution policy should require a working native lock. Re-enabling with a retained marker reapplies protection, but cannot cover the disabled interval. |
| Crash/startup recovery | Per-login Shell runtime state restores an active privacy screen after Shell startup handlers finish. Actual SIGKILL/restart is covered on the private GNOME 48.7 compositor with extension-enabled settings retained. GNOME's systemd startup crash policy may disable extensions after failure within its first minute, and a normal Wayland failure may end the login session. Decide whether the interval before extension loading or disabled-extension recovery warrants a separate native-lock mechanism. Marker writes use GNOME's asynchronous persistence; failure before a write completes and distribution-specific session termination remain manual checks. A new capture is taken after recovery; the old frozen frame is never saved. |
| Media across recovery and external changes | Resume uses the same unique D-Bus owner, preventing a restarted player with the same public name from being started. During native handoff media remains paused until unlock; disable leaves it paused. Decide how to handle external playback changes, pause failure, playback initiated while covered, and remembering which players were paused across a Shell crash. Currently the old session's media restore records do not survive a crash. |
| Monitor changes and placement | Layout changes request native locking. Prompt follows the pointer or uses an index/fixed coordinates; positions are clamped to a real display rather than a monitor gap. Decide whether to recapture on hotplug/rotation/scaling, use stable monitor connectors, or allow prompts to span displays. |
| Password editing/accessibility | Native PasswordEntry provides keyboard layout/IME handling and Unicode editing. Escape, Backspace, Return, inactivity clear, Ctrl+U and Normal-mode reveal remain; reveal follows GNOME policy. The limit is 512 UTF-8 bytes, with a native 512-character editing ceiling. Clipboard paste, middle-click paste, and desktop shortcuts are blocked. Decide permitted selection/navigation shortcuts, Caps Lock/layout indicators, screen-reader behavior, touch reveal, and whether reveal should time out. |
| Live settings and theme changes | CSS, saved effect selection/configuration, reduced motion, GNOME theme variants, and emergency shortcut settings update live; other presentation choices generally apply next activation. Decide whether every option should update live or whether sessions should use a settings snapshot. |
| Visual programs and effect budget | Ordinary editable JSON entries for Dim and Blur, Neo Rain, and City Grow are seeded only once for fresh profiles and initially inactive. All entries share the editor/renderer; users may edit or delete everything. Native clock dates follow the locale and reduced motion freezes animation. Arbitrary Shell JavaScript remains retired. Decide whether additional visual knobs, performance limits on large desktops, or a separately isolated programmable renderer are needed later. |
| First-install identification | The source installer knows whether the extension directory already exists. Standard ZIP installs have no hook, so extension/preferences initialization preserves any existing user settings. A legacy profile containing only untouched defaults cannot be distinguished from a new profile and receives inactive starter entries. Decide whether a future explicit import/reset workflow should replace that heuristic. Deleted libraries are never restored by updates or reinstalls. |
| Settings/version identity | UUID/schema remain unchanged; numeric version is 10 with version-name 1.0.1, repository URL is filled, and unlock-dialog session support exists only to manage cleanup/handoff. Decide when retired JS/debug/legacy keys should be removed and whether export/migration needs a dedicated UI. |
| Distribution/license/translation | GPL v3 and established human owner RisPNG are recorded in REUSE; gettext strings are listed but translations are not provided. Decide copyright completeness, GPL-only versus GPL-or-later intent, translation coverage, extensions.gnome.org submission, and release signing/distribution policy. Review current EGO guidelines before publication. |
| Legacy system artifacts | New scripts are user-local only. Decide whether to provide a dedicated migration tool for old system extension/schema copies; no privileged cleanup happens automatically. |
| Release acceptance | Decide the required manual test matrix and signoff. Automated checks do not establish a production security audit or compatibility with every advertised Shell version. |

## Manual acceptance matrix

- Activate with apps playing video, multiple monitors, negative monitor positions, scaling/rotation, overview open, and another modal active. Confirm either full keyboard/pointer protection or a clear activation failure.
- Try Super, Alt+Tab, Alt+F2, desktop/extension shortcuts, all mouse buttons, touch and scroll against applications. Verify only intended password input and reveal controls react.
- Check each layout/IME, Unicode passwords, Backspace, Escape, empty submission, wrong password, account denial, timeout, repeated Enter, retry timing, reveal concealment and auto-clear. Accept IME candidates with Enter; clear composition-only input with Escape, Ctrl+U and inactivity; check delayed engine responses after clearing. Use real GDM/PAM only in a disposable test account/session.
- Disable at every acquisition/await and while authenticating. Confirm no late overlay, no helper left alive, no stale successful result dismissing a new screen, and complete cleanup despite one teardown failure.
- Confirm native locking succeeds before overlay teardown; test denied native lock, normal automatic locking, idle blanking, suspend/resume, user switching and dialogs opened by existing applications while active. Verify media stays paused until the chosen endpoint.
- Test Shell restart/crash while active and after successful dismissal, including crash immediately after activation. Confirm recovery marker restoration, no obsolete password/frame persisted, and no unwanted reactivation after logout/login.
- Test playing/paused/stopped/disappearing/restarted MPRIS players, cancellation during Pause, externally changed playback and relocking before restoration completes.
- Repeat activation/dismissal and enable/disable cycles. Check actors, modal grabs, signals, sources, helpers, textures and memory return to baseline; inspect Shell logs for errors.
- Verify preferences, CSS and visual library operations, all three effects, clock placement, reduced motion, custom cursor images/colors, all placement/cursor modes, light/dark appearance, isolated install/update/uninstall, and the release archive on every supported version.

## Automated validation scope

Node and Python suites cover owned resources, authentication policy, cancellation, retries, recovery state, media restoration, native input ordering, saved preset initialization/validation, and isolated distribution scripts. GJS tests exercise actual subprocess I/O, cancellation, exits, and the ten-second timeout using a fake helper. The headless GNOME 48.7 Wayland suite exercises native screenshot textures, PasswordEntry editing/submission, modal input interception, cursor/focus restoration, Shell input-method composition clearing, multiple virtual monitors, live theme variants, MPRIS owners, GTK preferences, and actual compositor SIGKILL/restart recovery. Native virtual activation invokes the registered shortcut. A private fake GDM allows the real screen shield's handoff/unlock lifecycle to run; that coverage is explicitly skipped when the substitute is disabled. Actual account authentication, physical input devices, other GNOME releases, suspend, and full display-manager crash behavior remain manual checks.
